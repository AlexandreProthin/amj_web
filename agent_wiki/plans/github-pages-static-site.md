# Objective

Implement the static experiences defined in the [public heritage portal
specification](/specs/public-heritage-portal.md). Their published GitHub URLs
are encoded in three QR codes.

# Delivery branches

1. [Foundation and publishing](/plans/github-pages-foundation.md)
2. [Independent experiences](/plans/independent-experiences.md)
3. [Interactive church map](/plans/interactive-church-map.md)
4. [Identity and attribution](/plans/identity-and-attribution.md)
5. [Quality assurance and release](/plans/quality-and-public-release.md)
6. [QR codes and printed supports](/plans/qr-and-print-supports.md)

The first three branches can advance after foundation. Identity and attribution
must finish before release. Print work begins only after the live URLs and QR
codes are validated.

# Definition of success

All branch acceptance criteria pass; GitHub Pages serves the three experiences;
each QR code resolves to its target on a mobile device; and A4/cartel supports
use only final validated URLs.
